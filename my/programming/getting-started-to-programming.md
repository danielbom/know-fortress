# O que estudar

Antes de escolher uma linguagem, observe os padrões de vagas no Linkedin. As empresas não pedem só uma linguagem, mas uma combinação de linguagens e framework.
- Java com Spring Boot + Angular
- Python com FastAPI ou Django
Valide o mercado para ter certeza de que está escolhendo uma linguagem com demanda e também para ter um direcionamento do que estudar depois que você dominar ela.

* Com uma só linguagem escolhida, foque em lógica, programação orientada a objetos e estruturas de dados.
Neste momento, é comum achar que é necessário conhecer a linguagem inteira para entender ela de fato. Mas, o mais importante é que você desenvolva pensamento analitico. Isso só se desenvolve a partir da prática, com exercícios.

Em relação a prática, você já deve escrever código organizado, mesmo em simples exercícios.
Não é necessário saber nomes de padrões de projeto, mas já tente separar responsabilidades, evitar repetições e criar pequenas abstrações.

* E junto disso tudo é essencial que você aprenda o básico de git.
Versionamento de código hoje não é algo opcional. Então, se você criar um repositório para manter os exercícios que você faz no seu curso, você já vai estar também aprendendo a versionar o próprio código.

Depois que essa base estiver muito clara para você é hora de ir pro que de fato interessa em produção: APIs.
E aí vai fazer sentido tudo que falei mais cedo sobre frameworks usados com cada linguagem.

Mesmo que o seu objetivo seja trabalhar com frontend no futuro, você precisa entender como sistemas se comunicam.
Então estude REST, o protocolo HTTP, métodos como GET, POST, PUT, PATCH e DELETE e status code.
E aí finalmente você já pode criar as suas primeiras APIs com o framework escolhido.

Inicialmente não precisa se preocupar com banco de dados.
Você pode usar listas ou objetos em memória mesmo.
Mas vai chegar uma hora que você vai sentir falta de persistência.
E aí que entra o banco de dados.

Se você entendeu bem POO, modelar um banco de dados vai ficar bem mais fácil.
A diferença é que agora tanto entidades, quanto relacionamentos podem ser tabelas.
E de novo, você não precisa tudo de SQL ou todos os recursos do seu banco de dados.
Mas você precisa saber fazer modelagem, normalização, índices e constraints.
Porque você vai perceber que o banco de dados não serve só para guardar dados.
Mas serve pra proteger o seu sistema de erros, caso alguma regra falhe por exemplo.
(Ele dá suporte para garantir a consistencia da aplicação)

E pra fechar o ciclo, entra a parte de frontend.
Você precisa saber pelo menos o básico de JavaScript, HTML e CSS para conseguir dar valor a sua aplicação.
Quando você tem a perspectiva dos dois lados, você começa a ter um olhar mais crítico, tanto para implementar o backend quanto o frontend.
E aí você começa a enxergar o sistema como um todo.

Agora, uma dica final, mas muito importante.
Não tente apresar as coisas.
Não dá para estudar tudo isso em 3 semanas.
Não de verdade.
Você tem que se lembrar que você precisa carregar esse conhecimento que você aprendeu pro resto da sua vida.
E isso vai demandar tempo.
